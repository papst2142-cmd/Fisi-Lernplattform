============================================================================
 Fachinformatiker Lernplattform - Installer: installieren und selbst bauen
============================================================================

Ab Version 0.20 gibt es fertige Installer fuer Windows, Linux und macOS.
Alle bringen Python, CustomTkinter und Pillow bereits mit - auf dem
Zielrechner muss nichts zusaetzlich installiert werden.


TEIL A: INSTALLIEREN
============================================================================

Die Installer liegen auf der GitHub-Seite des Projekts unter "Releases"
(rechte Seitenleiste). Jeweils die Datei mit der hoechsten Versionsnummer
herunterladen.

WINDOWS  -  FISI-Lernplattform-Setup-<Version>.exe
----------------------------------------------------------------------------
1. Die Setup-Datei per Doppelklick starten.
2. Erscheint "Der Computer wurde durch Windows geschuetzt": auf "Weitere
   Informationen" und dann "Trotzdem ausfuehren" klicken. (Der Installer
   ist nicht kostenpflichtig signiert.)
3. Dem Assistenten folgen. Es werden keine Admin-Rechte benoetigt, das
   Programm wird nur fuer den aktuellen Benutzer installiert.
4. Das Programm steht danach im Start-Menue unter
   "Fachinformatiker Lernplattform" (bis 0.60.1: "FISI Lernplattform").
   Deinstallieren ueber Einstellungen -> Apps.
Ab Version 0.22 aktualisiert sich das Programm selbst (siehe LIESMICH.txt,
Abschnitt UPDATES). Aeltere Versionen: das neue Setup einfach ueber die alte
Version installieren.

LINUX (Debian, Ubuntu, Linux Mint)  -  fisi-lernplattform_<Version>_amd64.deb
----------------------------------------------------------------------------
1. Im Download-Ordner ein Terminal oeffnen.
2. Installieren mit:
     sudo apt install ./fisi-lernplattform_<Version>_amd64.deb
   Mit derselben Zeile wird auch eine neue Version eingespielt.
3. Start ueber das Startmenue ("Fachinformatiker Lernplattform") oder im
   Terminal mit
     fisi-lernplattform
Entfernen:  sudo apt remove fisi-lernplattform

App Center (Doppelklick auf die .deb-Datei): Es kann nur die erste
Installation. Bei jeder heruntergeladenen .deb-Datei warnt es
"moeglicherweise unsicher", bei einer schon installierten Version zeigt es
nur ein graues "Installiert". Fuer Updates deshalb die Zeile aus Schritt 2.

Alte Startdatei: Wer frueher selbst eine Startdatei fisi-lernplattform.desktop
in ~/.local/share/applications/ angelegt hat (zum Beispiel mit einem fruehen
Installationsskript), verschiebt sie mit
     mv ~/.local/share/applications/fisi-lernplattform.desktop ~/fisi-lernplattform.desktop.alt
und meldet sich danach einmal ab und wieder an. Wer so eine Datei nicht hat,
muss nichts tun.

LINUX (alle anderen Distributionen)  -  FISI-Lernplattform-<Version>-x86_64.AppImage
----------------------------------------------------------------------------
1. Die Datei ausfuehrbar machen:
     chmod +x FISI-Lernplattform-*.AppImage
   (oder im Dateimanager: Rechtsklick -> Eigenschaften -> "Als Programm
   ausfuehren" erlauben)
2. Per Doppelklick starten. Eine Installation ist nicht noetig.

ANDROID  -  FISI-Lernplattform-<Version>-Android.apk
----------------------------------------------------------------------------
1. Auf dem Handy im Browser die Releases-Seite oeffnen und die .apk-Datei
   herunterladen.
2. Die Datei oeffnen und Android erlauben, Apps aus dieser Quelle zu
   installieren (fragt nur beim ersten Mal).
3. "Installieren" tippen. Warnt Google Play Protect: "Weitere Details" ->
   "Trotzdem installieren".
Updates bietet die App selbst an (Einstellungen -> Updates). Einrichtung
des Abgleichs mit dem PC: LIESMICH.txt, Abschnitt ABGLEICH PC UND HANDY.

MACOS  -  FISI-Lernplattform-<Version>-macOS-arm64.dmg / -intel.dmg
----------------------------------------------------------------------------
Welche Datei? Apfel-Menue -> "Ueber diesen Mac": Steht dort "Chip Apple
M1/M2/M3/..." die arm64-Datei nehmen, steht dort "Prozessor Intel" die
intel-Datei.
1. Die .dmg-Datei per Doppelklick oeffnen.
2. "FISI-Lernplattform" auf die Verknuepfung "Programme" ziehen.
3. Beim ersten Start meldet macOS, dass die App nicht geoeffnet werden
   kann (sie ist nicht bei Apple beglaubigt). Dann im Ordner "Programme"
   mit Rechtsklick auf FISI-Lernplattform -> "Oeffnen" -> "Oeffnen".
   Das ist nur einmal noetig. Unter neueren macOS-Versionen alternativ:
   Systemeinstellungen -> Datenschutz & Sicherheit -> "Dennoch oeffnen".

Die Lernfortschritte bleiben bei Updates und Deinstallation erhalten
(Speicherorte siehe LIESMICH.txt).


TEIL B: INSTALLER BAUEN
============================================================================

Die Versionsnummer wird immer mit EINEM Befehl gesetzt, zum Beispiel:
  python build.py --setze-version 0.22
Das traegt sie gleichzeitig in app_gui.py, LIESMICH.txt, das Inno-Setup-
Skript und die Handy-App (mobile/src/main.py, mobile/pyproject.toml samt
interner Android-Versionsnummer build_number) ein. Von dort landet sie automatisch in Programmfenster, Installern,
Dateinamen, Windows-Dateieigenschaften und macOS-App. Vor jedem Build prueft
build.py, dass die Version ueberall gleich ist, und bricht sonst ab.

AUTOMATISCH PER GITHUB ACTIONS (alle drei Betriebssysteme)
----------------------------------------------------------------------------
Voraussetzung: Das Projekt liegt in einem GitHub-Repository.

Variante 1 - Release mit Versions-Tag (empfohlen):
  1. python build.py --setze-version <neue Version> und in AENDERUNGEN.md
     einen Abschnitt "## <neue Version>" mit den Neuerungen anlegen, dann
     committen und pushen. (Ohne diesen Abschnitt bricht der Release ab -
     der Text erscheint im Release und im Update-Fenster des Programms.)
  2. Einen passenden Tag setzen und pushen, z.B. fuer Version 0.22 bzw.
     die Fehlerbehebung 0.22.1:
       git tag v0.22            (bzw. git tag v0.22.1)
       git push origin v0.22    (bzw. git push origin v0.22.1)
  3. GitHub baut jetzt (ca. 10-20 Minuten) auf Windows, Linux und macOS
     sowie die Android-App und legt unter "Releases" ein neues Release mit
     allen Installern und der .apk an.
     Den Fortschritt zeigt der Reiter "Actions".
  Passt der Tag nicht zu APP_VERSION, bricht der Lauf mit einer Meldung ab.

Variante 2 - Testlauf von Hand:
  Auf GitHub im Reiter "Actions" links "Installer bauen" waehlen und auf
  "Run workflow" klicken. Die Installer liegen danach auf der Seite des
  Laufs ganz unten unter "Artifacts" (ohne Release).

LOKAL (nur fuer das eigene Betriebssystem)
----------------------------------------------------------------------------
Windows:
  1. Einmalig Inno Setup 6 installieren: https://jrsoftware.org/isdl.php
  2. build_windows.bat per Doppelklick ausfuehren.
  3. Ergebnis: installer_output\FISI-Lernplattform-Setup-<Version>.exe

Linux (Debian-basiert):
  1. ./build_linux.sh ausfuehren.
  2. Ergebnis: installer_output/fisi-lernplattform_<Version>_amd64.deb
     (die AppImage nur, wenn appimagetool installiert ist)

macOS:
  1. python3 -m pip install -r requirements-build.txt
  2. python3 build.py
  3. Ergebnis: installer_output/FISI-Lernplattform-<Version>-macOS-<Arch>.dmg

Nur die Anwendung ohne Installer (Ordner dist/FISI-Lernplattform):
  python build.py --nur-app

ANDROID-APP (Ordner mobile/)
----------------------------------------------------------------------------
Die .apk baut GitHub Actions (Job "android") mit Flet. Signiert wird sie
mit einem festen Schluessel aus den Repository-Secrets
ANDROID_KEYSTORE_BASE64 und ANDROID_KEYSTORE_PASSWORD - nur so installiert
Android neue Versionen als Update. Eine Kopie des Schluessels liegt ausserhalb
des Repositorys (Ordner FISI-Android-Schluessel); nicht verlieren.

Die Handy-App am PC ausprobieren (ohne Handy):
  python -m pip install "flet[all]==1.0.1"
  python mobile/src/main.py          (eigenes Fenster)
  python mobile/src/main.py --web    (im Browser, http://localhost:8550)
Selbsttest aller Seiten ohne Bildschirm:
  python mobile/src/main.py --selbsttest

Lokal bauen (laedt beim ersten Mal Flutter, JDK und Android-SDK, mehrere
GB):
  python mobile/vorbereiten.py
  cd mobile
  flet build apk

Hinweis: Der Ordner installer_output ist per .gitignore vom Repository
ausgeschlossen - fertige Installer gehoeren in GitHub-Releases, nicht in
die Versionsverwaltung.
